# API利用設計（モデル・コスト）

対象範囲: LLM（OrcaRouter経由）の呼び出しコストのみ。`handoff`（エージェント・専門家への相談リンク）や`paywall`（追加リサーチの課金）は`disabled`のモック実装であり本ドキュメントの対象外（[components/result/ActionSection.tsx](../components/result/ActionSection.tsx)）。性能グレード（松竹梅＝モデル選択）とは独立した別軸の未実装機能であり、モデルを松にしても自動的に実装されるものではない。

前提: LLM呼び出しは全て OrcaRouter（OpenAI互換ルーター、`baseURL: https://api.orcarouter.ai/v1`）経由。料金は **OrcaRouterが接続先モデルのOpenAI公式価格に準拠している前提**で試算する（OrcaRouter独自の上乗せ有無は未確認）。モデル価格は `GET /v1/models`（OrcaRouter）のレスポンスから取得（2026-08-14）。

## 1. 利用モデルと切り替え方法

| 用途 | 呼び出し箇所 | 環境変数 | 現在値 | Web Search |
|---|---|---|---|---|
| ヒアリング質問生成 | `/api/interview` | `ORCAROUTER_MODEL` | `openai/gpt-4o-mini` | なし |
| 基礎調査（Pass1） | `/api/research` 内 | `ORCAROUTER_FACT_MODEL` | `openai/gpt-4o-mini-search-preview` | あり |
| 詳細生成（Pass2） | `/api/research` 内 | `ORCAROUTER_MODEL` | `openai/gpt-4o-mini` | なし（search系モデルの出力上限〈実測1,000〜1,500トークン〉を回避するため意図的に無効） |

**切り替え方法**: Vercel Environment Variables の `ORCAROUTER_MODEL` / `ORCAROUTER_FACT_MODEL` を書き換えて再デプロイする（コード変更不要、`lib/OrcaRouterClient.ts` が実行時に読む）。`ORCAROUTER_FACT_MODEL` を空にするとPass1自体をスキップする設計。

## 2. リサーチ設計（Pass1 / Pass2の役割分担）

- **Pass1**（`prompts/research_facts.md`）: Web検索を行い、事実・相場・制度情報を収集する担当。検索を行うのはこのステップのみ。
- **Pass2**（`prompts/research_system.md`）: Pass1が集めた事実と一般知識のみを根拠に、比較結果（`ResearchResult`）を構造化生成する担当。Pass2自身は検索しない。

Pass1が探す対象は2種類:

1. **ベースラインの事実**（業界動向・年収相場・必要な資格・リスク実例など）
2. **代替ルートの実在探索**: ユーザーが素朴に想定しているであろう「ゼロから全部自分で用意するルート」以外に、同じゴール（`goal.description`）へ到達できる別の手段が実在しないかを探す。カテゴリの着眼点は `goal.type` によって出し分ける:
   - `independence`（独立・資産保有を伴うことが多い）: 第三者承継・事業承継／資産を借りる・間借りする仕組み／雇われながら学べる制度／自治体・国の補助金
   - `career_change`（転職）: 未経験者向け特別選考・ポテンシャル採用／職業訓練校・スクールと教育訓練給付金／副業・フリーランスでの実績づくり／人材紹介・紹介予定派遣
   - 上記に当てはまらないテーマは `goal.description` から都度カテゴリを設定する

この出し分けにより、資産保有を伴わないテーマ（転職等）に対して不動産・間借りのような無関係なカテゴリを検索させない。

## 3. トークン数の設計根拠（スキーマ構造に基づく実測内訳）

以降のコスト試算は、実際の `prompts/research_system.md` と `types/research.ts`（`researchResultSchema`）を `tiktoken`（`o200k_base`）で計測した数値に基づく。Pass2に渡す入力（システムプロンプト＋JSON Schema＋ヒアリング回答）とスキーマが要求する出力構造はモデルを変えても同一のため、**入出力トークン数の土台は全グレード共通**として扱う。

### 入力（Pass2、リクエストごとに固定される部分）

| 構成要素 | トークン数 | 備考 |
|---|---|---|
| `research_system.md`（システムプロンプト本文） | 5,758 | 固定 |
| `researchResultSchema`（JSON Schema定義、`response_format`で毎回送信） | 2,349 | 固定 |
| ヒアリング回答・プロフィール（ユーザー入力） | 約120〜300 | 回答数・文字数で変動 |
| **合計** | **約8,200〜8,300** | 実測値8,226と整合。固定分8,107はプロンプトキャッシュ対象（実測でも7,040トークンがキャッシュ扱い） |

### 出力（生成されたJSONの構造別トークン数）

| フィールド | トークン数 | 出力全体比 | スキーマ上の制約（`types/research.ts`） |
|---|---|---|---|
| `summary` | 167 | 4% | 固定4項目（fitScore/availableFunds/survivalPeriod/relevantExperience） |
| `currentPath` | 682 | 16% | 「今のまま」1件、`yearlyScenes`(y1/y3/y5)必須 |
| `targetPaths`×3 | 3,164 | **72%** | `targetPaths.length(3)` で必ず3件固定。1件あたり約1,000〜1,100トークン（内訳: `yearlyScenes` 約320〜360、`plan` 3件で約120〜150、`risks` 約100〜115、`outlook`+`detail` 約75〜85、`series`79、`tuneFactors`38） |
| `checks` | 138 | 3% | `min(3).max(8)` |
| `sources` | 212 | 5% | 可変 |
| **合計** | **約4,400〜5,300** | | `targetPaths.length(3)`固定により出力の7割超を`targetPaths`が占める |

## 4. Web Search回数の設計根拠

検索回数は `targetPaths` の件数ではなく、**Pass1が探す対象の数**（2章）から積み上げる: ベースライン1 ＋ 代替ルート4カテゴリ×1 ＝ **5回**（$25/1,000回×5＝$0.125）。

以下は、この見積もりを裏付ける実測結果（`gpt-4o-mini-search-preview`、テーマ「いちご農園を始めたい」）。

| # | クエリ | 見つかった情報源 |
|---|---|---|
| 1 | 初期費用相場・必要な資格・要件 | 3件（具体的な金額データ） |
| 2 | 第三者承継・事業承継の制度 | 3件（自治体の継承奨励金等） |
| 3 | 農地を借りる仕組み（農地バンク等） | 5件（特定農地貸付法・都市農地貸借法等） |
| 4 | 雇われながら学べる制度 | 0件（この道自体、特定制度に紐づきにくい性質のため出典なしで成立させてよい） |
| 5 | 補助金・支援窓口 | 6件／4URL（就農準備資金・青年等就農資金等） |

career_change向けカテゴリ（テーマ「デザイナーに転職したい」）でも同様に検証済み: 未経験者向け求人3件・教育訓練給付金4件・ポートフォリオ制作サービス4件・人材紹介3件（4カテゴリ全てで実在サービスを発見）。

Pass1のトークン分はこの5クエリの実測値から算出: prompt合計562／completion合計2,870トークン。

## 5. 性能グレード比較（松竹梅）

| グレード | 構成 | ヒアリング / Pass1 / Pass2 | 1回あたり | 現状比 |
|---|---|---|---|---|
| 🍃 梅（エコ性能・現行） | 2パス、Web Searchは基礎調査のみ | gpt-4o-mini / gpt-4o-mini-search-preview / gpt-4o-mini | **約$0.03（≒4.5円）** | 1x |
| 🎋 竹（推奨性能） | Pass1は検索ネイティブ機、Pass2はgpt-5世代の標準モデル | gpt-5.1 / gpt-5-search-api / gpt-5.1 | **約$0.22（≒33円）** | 約7.3x |
| 🌲 松（最高性能） | Pass2をカタログ最上位の推論モデルに | gpt-5.1 / gpt-5-search-api / gpt-5.5-pro | **約$1.4〜$2.3（≒210〜345円）** | 約47〜77x |

竹・松ともWeb Search呼び出し課金（$25/1,000回×5）が土台コストの主要因。竹・松の差はPass2モデルの単価差（gpt-5.1: $1.25/$10 per M → gpt-5.5-pro: $30/$180 per M）による。

### 🍃 梅（エコ性能）

| 呼び出し | input | output | 料金 |
|---|---|---|---|
| ヒアリング生成 | 1,568 | 248 | $0.0004 |
| 基礎調査（トークン分＋Web Search） | 961 | 763 | $0.0256 |
| 詳細生成（8,226中7,040がキャッシュ） | 8,226 | 5,292 | $0.0039 |
| **合計** | | | **約$0.030** |

現行は1つの自由記述プロンプトにPass1を任せているため、5カテゴリを明示的に分けて検索させる竹・松よりカバレッジが浅くなりうる。

### 🎋 竹（推奨性能）

現行の `gpt-4o` 系より新しく、単価も安い `gpt-5.1` / `gpt-5-search-api`（いずれも $1.25/$10 per Mトークン）に統一する。スキーマ構造は変えないため、入出力トークン量は3章の実測ベース（入力約8,200〜8,300／出力約4,400〜5,300）をそのまま使う。

| 内訳 | 料金 |
|---|---|
| ヒアリング生成（入力1,568／出力248） | $0.0044 |
| Pass1トークン分（4章の5クエリ実測: prompt562／completion2,870） | $0.029 |
| Pass1 Web Search（5回） | $0.125 |
| Pass2（入力8,300×$1.25/1M ＋ 出力5,300×$10/1M） | $0.063 |
| **合計** | **約$0.22** |

### 🌲 松（最高性能）

Pass2のみカタログ最上位の推論モデル `gpt-5.5-pro`（$30/$180 per Mトークン）に置き換える。ヒアリング・Pass1は竹と同じ（$0.0044+$0.029+$0.125＝$0.158）。

Pass2: 入力8,300×$30/1M=$0.249、出力5,300×$180/1M=$0.954 → **$1.20**（可視出力のみの下限値）。
推論系モデルは可視出力の裏で「隠れ思考トークン」も課金されるケースがあるため、可視出力の2倍を仮置きした上限値も併記: 出力10,600×$180/1M=$1.908 → Pass2で**$2.16**（この倍率は未実測の目安）。

| シナリオ | 合計 |
|---|---|
| 下限（可視出力のみ） | $0.158+$1.20 ≒ **$1.4** |
| 上限（隠れ思考トークン込み） | $0.158+$2.16 ≒ **$2.3** |

**運用上の注意**: 実運用投入前に、応答時間（推論モデルは数分単位になりうる）・現行の `maxDuration=120`（Vercel）との整合・JSON Schema出力の安定性を実機で検証すること。
