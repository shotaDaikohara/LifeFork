# API利用設計（モデル・コスト）

前提: LLM呼び出しは全て OrcaRouter（OpenAI互換ルーター、`baseURL: https://api.orcarouter.ai/v1`）経由。
料金は **OrcaRouterが接続先モデルのOpenAI公式価格に準拠している前提**で試算（OrcaRouter独自の上乗せ有無は未確認）。実際の価格は `GET /v1/models`（OrcaRouter）のレスポンスから取得（2026-08-14）。

## 1. 現在利用中のモデルと切り替え方法

| 用途 | 呼び出し箇所 | 環境変数 | 現在値 | Web Search |
|---|---|---|---|---|
| ヒアリング質問生成 | `/api/interview` | `ORCAROUTER_MODEL` | `openai/gpt-4o-mini` | なし |
| 基礎調査（Pass1） | `/api/research` 内 | `ORCAROUTER_FACT_MODEL` | `openai/gpt-4o-mini-search-preview` | あり |
| 詳細生成（Pass2） | `/api/research` 内 | `ORCAROUTER_MODEL` | `openai/gpt-4o-mini` | なし（search系モデルの出力上限〈実測1,000〜1,500トークン〉回避のため意図的に無効） |

**切り替え方法**: Vercel Environment Variables の `ORCAROUTER_MODEL` / `ORCAROUTER_FACT_MODEL` を書き換えて再デプロイするだけ（コード変更不要、`lib/OrcaRouterClient.ts` が実行時に読む）。`ORCAROUTER_FACT_MODEL` を空にするとPass1自体をスキップする。

## 2. トークン数の根拠（スキーマ構造に基づく実測内訳）

以降のコスト試算は、実際の `prompts/research_system.md` と `types/research.ts`（`researchResultSchema`）から `tiktoken`（`o200k_base`）で実測した数値に基づく。全モデル共通で、Pass2に渡す入力の中身（システムプロンプト＋JSON Schema＋ヒアリング回答）とスキーマが要求する出力構造は変わらないため、**モデルを変えても入出力トークン数の土台は同じ**という前提で試算している。

### 入力（Pass2、リクエストごとに固定される部分）

| 構成要素 | トークン数 | 備考 |
|---|---|---|
| `research_system.md`（システムプロンプト本文） | 5,758 | 固定 |
| `researchResultSchema`（JSON Schema定義、`response_format`で毎回送信） | 2,349 | 固定 |
| ヒアリング回答・プロフィール（ユーザー入力） | 約120〜300 | 回答数・文字数で変動 |
| **合計** | **約8,200〜8,300** | 実測値8,226と整合。うち固定分8,107はプロンプトキャッシュ対象（実測でも7,040トークンがキャッシュ扱い） |

### 出力（実際に生成されたJSONの構造別トークン数、実測サンプルより）

| フィールド | トークン数 | 出力全体比 | スキーマ上の制約（`types/research.ts`） |
|---|---|---|---|
| `summary` | 167 | 4% | 固定4項目（fitScore/availableFunds/survivalPeriod/relevantExperience） |
| `currentPath` | 682 | 16% | 「今のまま」1件、`yearlyScenes`(y1/y3/y5)必須 |
| `targetPaths`×3 | 3,164 | **72%** | `targetPaths.length(3)` で**必ず3件固定**。1件あたり約1,000〜1,100トークン（内訳: `yearlyScenes` 約320〜360、`plan` 3件で約120〜150、`risks` 約100〜115、`outlook`+`detail` 約75〜85、`series`79、`tuneFactors`38） |
| `checks` | 138 | 3% | `min(3).max(8)` |
| `sources` | 212 | 5% | 可変（実測4件） |
| **合計** | **約4,400** | | 実測完了トークン数は生成内容の厚みで5,300前後まで変動 |

→ **出力トークンの7割超は `targetPaths` が占め、これはスキーマが3道固定を要求していることに直接起因する**。道の数や `plan`/`risks` の項目数を増減しない限り、出力トークン数はモデルを変えても大きくは動かない。

## 3. 性能グレード比較（松竹梅）

| グレード | 構成 | ヒアリング / Pass1 / Pass2 | 1回あたり | 現状比 |
|---|---|---|---|---|
| 🍃 梅（エコ性能・現行） | 2パス、Web Searchは基礎調査のみ | gpt-4o-mini / gpt-4o-mini-search-preview / gpt-4o-mini | **約$0.03（≒4.5円）** | 1x |
| 🎋 竹（推奨性能） | Pass1は検索ネイティブ機、Pass2はgpt-5世代の標準モデル | gpt-5.1 / gpt-5-search-api / gpt-5.1 | **約$0.28（≒42円）** | 約9.3x |
| 🌲 松（最高性能） | Pass2をカタログ最上位の推論モデルに | gpt-5.1 / gpt-5-search-api / gpt-5.5-pro | **約$1.4〜$2.4（≒210〜360円）** | 約47〜80x |

竹・松ともWeb Search呼び出し課金（$25/1,000回、想定8回）が土台コストの主要因。竹・松の差はPass2モデルの単価差（gpt-5.1: $1.25/$10 per M → gpt-5.5-pro: $30/$180 per M）による。

### 🍃 梅（エコ性能）— 現状構成・実測値

「いちご農園を始めたい」テーマで実際にAPIを呼び出し、トークン数を実測。

| 呼び出し | input | output | 料金 |
|---|---|---|---|
| ヒアリング生成 | 1,568 | 248 | $0.0004 |
| 基礎調査（トークン分 + Web Search1回） | 961 | 763 | $0.0256 |
| 詳細生成（8,226中7,040がキャッシュ） | 8,226 | 5,292 | $0.0039 |
| **合計** | | | **約$0.030** |

※ Web Search回数「1回」は、APIレスポンス（`usage`）に検索回数を示すフィールドが無いため、実測時に観測された`sources`件数からの推定にすぎない。竹・松の「8回」は`research_facts.md`が実際に指示する検索対象（後述）から積み上げた**設計上の仮定**であり、性質が異なる未検証値どうしを比べている点に注意。実際には梅も8回相当まで増える可能性があるし、逆もありうる。

※ このドキュメントはLLM（OrcaRouter）呼び出しのコストのみを対象とする。現行実装は `handoff`（エージェント・専門家への相談リンク）と `paywall`（追加リサーチの課金）を `disabled` のモックのまま残しており（[components/result/ActionSection.tsx](../components/result/ActionSection.tsx)）、これは性能グレード（松竹梅＝モデル選択）とは独立した「未実装の機能」であって、モデルを松にしても自動的に実装されるものではない。

### 🎋 竹（推奨性能）

現行の `gpt-4o` 系より新しく、単価もむしろ安い `gpt-5.1` / `gpt-5-search-api`（いずれも $1.25/$10 per Mトークン）に統一する案。**スキーマ構造は変えない**ため、入出力トークン量は2章の実測ベース（入力約8,200〜8,300／出力約4,400〜5,300）をそのまま使う。

計算: 入力 8,300×$1.25/1M=$0.0104、出力 5,300×$10/1M=$0.053 → Pass2で約$0.063。ヒアリング生成（入力1,568/出力248）は約$0.0044。Pass1のトークン分は約$0.009。

**Web Search回数の根拠（訂正）**: 検索は `targetPaths`3件の数ではなく、**実際に検索を行うPass1（`research_facts.md`）が何を探すよう指示されているか**から積み上げる。Web検索するのはPass1だけで、Pass2は検索しない（`research_system.md`は「基礎調査(facts)や一般知識で実在が確認できるものだけを使うこと」と明記、Pass2自身は検索しない設計）。`research_facts.md`が明示的に検索対象として挙げているのは:

1. ベースラインの事実（業界動向・年収相場・必要な資格・リスク実例など） — 1〜2クエリ
2. 「素朴なフルコース以外の別ルート」の**実在探索**、具体的には4カテゴリ:
   - 第三者承継・事業承継の制度・支援窓口
   - 資産を借りる・間借りする仕組み
   - 雇われながら学べる制度
   - 自治体・業界団体・国の補助金・支援窓口

   このうち「実在確認」に留まる軽い検索ではなく、**そもそもテーマに存在するかを探す**ため、カテゴリごとに探索1回＋見つかった場合の詳細確認1回を要すると見込む。4カテゴリ全てで何かが見つかるとは限らないため平均1.5クエリ/カテゴリと仮定 → 4×1.5=6

合計: ベースライン1.5 + 代替ルート探索6 = **7.5 → 8回**（$25/1,000回×8＝$0.20）を採用。5〜10回のレンジも参考として付す。

| シナリオ | 回数 | 料金（検索分） |
|---|---|---|
| 少なめ | 5回 | $0.125 |
| **採用** | **8回** | **$0.20** |
| 多め | 10回 | $0.25 |

合計: $0.0044（ヒアリング）+ $0.009（Pass1トークン分）+ $0.20（検索8回）+ $0.063（Pass2）**≒ $0.28**（レンジで$0.20〜$0.33）

### 🌲 松（最高性能）

Pass2のみカタログ最上位の推論モデル `gpt-5.5-pro`（$30/$180 per Mトークン）に置き換える案。ヒアリング・Pass1は竹と同じ（$0.0044+$0.009+$0.20＝$0.213）。

Pass2: 同じ出力構造（`targetPaths`×3が中心）を前提に入力8,300×$30/1M=$0.249、出力5,300×$180/1M=$0.954 → **$1.20**（可視出力のみの下限値）。
推論系モデルは可視出力の裏で「隠れ思考トークン」も課金されるケースがあり、その分を可視出力の2倍と仮置きした場合の上限値は出力10,600×$180/1M=$1.908 → Pass2だけで**$2.16**。
※ この2倍という係数は実測できていない、あくまで目安の上限として扱うこと。

合計: 下限 $0.213+$1.20 **≒ $1.4**／上限 $0.213+$2.16 **≒ $2.4**

**運用上の注意**: 実運用投入前に、応答時間（推論モデルは数分単位になりうる）・現行の `maxDuration=120`（Vercel）との整合・JSON Schema出力の安定性を実機で検証すること。
